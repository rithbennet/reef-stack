## In one paragraph

Matt Pocock's skills are small Markdown instructions for coding agents. You install them as a Claude Code plugin or copy them in with skills.sh. They target four ways agent work goes wrong (below). Grilling comes first. Then the main flow runs `idea → /to-spec → /to-tickets → /implement` (`<plugin>/CHANGELOG.md:187`), with `/tdd` inside the build and `/code-review` at the end. The README splits skills by who can call them. For user-invoked skills, "their job is to orchestrate". Model-invoked skills "hold the reusable discipline" ([README L211](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/README.md#L211)). Many user-invoked skills are thin wrappers: `/grill-me` is one line that calls `grilling`. Each project keeps one glossary file and short ADRs, and most skills read them. Matt contrasts this with GSD, BMAD and Spec-Kit, which he says "take away your control and make bugs in the process hard to resolve" ([README L17](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/README.md#L17)).

## The four failure modes

The README presents these as "common failure modes I see with Claude Code, Codex, and other coding agents" ([L111](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/README.md#L111); `<plugin>/README.md:86`). Each item gives the upstream link first, then the line in the installed README.

1. **"#1: The Agent Didn't Do What I Want"** ([L113](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/README.md#L113); `:88`). Fix: a grilling session, with `/grill-me` for non-code work or `/grill-with-docs` ([L125-L126](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/README.md#L125-L126); `:100-101`). "Use them _every_ time you want to make a change." ([L128](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/README.md#L128); `:103`)
2. **"#2: The Agent Is Way Too Verbose"** ([L130](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/README.md#L130); `:105`). Fix: "a shared language. It's a document that helps agents decode the jargon used in the project." ([L140](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/README.md#L140); `:115`). It comes built into `/grill-with-docs`, which also helps you "document hard-to-explain decisions in ADR's." ([L156](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/README.md#L156); `:131`). Upstream calls the file `GLOSSARY.md` ([L220](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/README.md#L220)). The installed copy calls it `CONTEXT.md` (`:195`).
3. **"#3: The Code Doesn't Work"** ([L167](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/README.md#L167); `:142`). Fix: "the usual tranche of feedback loops: static types, browser access, and automated tests." ## Skills that matter for reef-stack

Paths are under `<plugin>/skills/`. Upstream uses the same path and almost the same text, unless the row says otherwise. "(user)" means user-invoked and "(model)" means model-invoked.

| Skill | What it tells the agent to do | Path |
|---|---|---|
| `grilling` (model) | Interview in rounds. Each round asks the whole "frontier": every decision whose prerequisites are settled. Number the questions and give a recommended answer for each. Look facts up yourself, with a sub-agent. Only decisions go to the user. Stop when the frontier is empty and the user confirms. | `productivity/grilling/SKILL.md:6-28` |
| `grill-me`, `grill-with-docs` (user) | One-line wrappers. `grill-me` calls `grilling`. `grill-with-docs` calls `grilling` and `domain-modeling`. | `productivity/grill-me/SKILL.md:7`, `engineering/grill-with-docs/SKILL.md:7` |
| `domain-modeling` (model) | Challenge terms against the glossary, sharpen vague words, test edge cases, and check claims against the code. Update the glossary as each term settles. A glossary entry is a bold term, a definition of one or two sentences, and an `_Avoid_:` list of synonyms, with no implementation detail. An ADR is 1-3 sentences in `docs/adr/0001-slug.md`. Offer one only when the decision is hard to reverse, surprising without context, and a real trade-off. | `engineering/domain-modeling/SKILL.md:44-74`, `CONTEXT-FORMAT.md:5-30` (upstream: `GLOSSARY-FORMAT.md`), `ADR-FORMAT.md:3-37` |
| `to-spec` (user) | Don't interview. Explore the code, then agree the test seams with the user (as few as possible, as high as possible). Write the spec: problem, solution, a long list of user stories, implementation and testing decisions, out of scope. No file paths. Publish it to the tracker as `ready-for-agent`. | `engineering/to-spec/SKILL.md:7-75` |
| `to-tickets` (user) | Prefactor first. Cut the work into tracer-bullet vertical slices, each with its blocking edges. Use expand-contract for wide refactors. Show the breakdown and revise it until the user approves. Publish one file per ticket under `.scratch/<feature>/issues/`, or as native tracker issues. | `engineering/to-tickets/SKILL.md:23-77` |
| `tdd` (model) | Test behaviour through public interfaces, and only at seams the user agreed. Write the failing test before the code, one slice per cycle. Refactoring belongs to review, not the loop. Anti-patterns: tests tied to the implementation, tautological tests, horizontal slicing. | `engineering/tdd/SKILL.md:12-38` |
| `diagnosing-bugs` (model) | Redact secrets. Phase 1 "is the skill": before any theory, build and run one fast, deterministic command that fails on this exact bug. Then shrink the repro and rank 3-5 testable hypotheses. Tag debug logs. Add a regression test at a correct seam, then clean up. | `engineering/diagnosing-bugs/SKILL.md:12-138` |
| `improve-codebase-architecture` (user) | Scope the search to recent git hot spots. Send a sub-agent to find shallow modules. Write the candidates to an HTML report in the temp dir, then grill the user on the one they pick. | `engineering/improve-codebase-architecture/SKILL.md:3-40` |
| `retro` (user) | After a session, suggest changes to the agent's environment, not the code: navigation pointers, automated checks, reviewer standards, steering moved out of AGENTS.md, tool cost, access to information. A mechanical rule becomes a lint rule, hook or CI job, not prose. List the most severe first. | Installed: `in-progress/retro/SKILL.md:7-44` (not in the plugin). Upstream: `engineering/retro/SKILL.md`, same text |
| `handoff` (user) | Write a handoff doc to the OS temp dir, not the repo. Add a "suggested skills" section. Link existing specs, ADRs and commits instead of copying them. Redact secrets. | `productivity/handoff/SKILL.md:8-16` |
| `writing-for-agents` (model) | A reference for writing skills and AGENTS.md/CLAUDE.md files. Word "context pointers" with care. Weigh the cost to the agent's context against the cost to the human. Move material that only some cases need behind a pointer. Give each step a clear test for done. Use "leading words". Say what to do, not what not to do. Cut duplicates and lines that change nothing. | `productivity/writing-for-agents/SKILL.md:10-81` |

## Take / leave for reef-stack

_Our reading, not Matt's._

- **Take grilling as the default first step.** The skill is about 20 lines and works on its own. Its split (the agent finds facts, the user makes decisions) and its recommended answer per question suit a personal playbook.
- **Take the glossary + ADR pair, with the three-part ADR test.** Name the file `GLOSSARY.md`. Upstream renamed it in 1.3.0, and its skills no longer read `CONTEXT.md`.
- **Take the `to-tickets` slice rules as reef-stack's ticket format.** Each slice is vertical, fits one fresh context window, and lists its blockers. Prefactoring comes first. Wide changes use expand-contract.
- **Take two rules.** From `diagnosing-bugs`: no hypothesis until a command fails on the bug. From `retro`: turn each mechanical rule into an automated check.
- **Leave the tracker plumbing** (`/setup-matt-pocock-skills`, triage labels, `ready-for-agent`) unless reef-stack adopts a tracker. One local file per ticket may be enough.
- **Pick one install route.** The README warns that "installing both gives you every skill twice" ([L27](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/README.md#L27)). The plugin also changes under you: 1.2.3 is installed, upstream is 1.3.1. If reef-stack edits a skill, fork it at a pinned commit and drop the plugin copy.
