## In one paragraph

pstack is a Cursor plugin of skills that captures how poteto ships code with agents. You start every serious task with `/poteto-mode`. It "picks from a set of playbooks, and runs the other skills as the steps need them" ([README.md:34](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/README.md#L34)), and it copies the playbook's steps into a todo list verbatim ([README.md:85](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/README.md#L85)). Short principle skills give the agent named rules, and you steer by saying a name: "You don't invoke principles. You use their names to steer." ([docs/guide/08-principles.md:5](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/docs/guide/08-principles.md#L5)). The core bet is depth before breadth. First make one agent's work checkable, mostly through a generated verify skill that drives the real app. Then run many agents. Long work runs in one of two ways. One chat can loop to a checkable finish condition (Autonomous run). Or a coordinator chat that never writes code can run a fleet from tables on disk (Orchestrate).

- **23 playbooks**, one file each in `skills/poteto-mode/playbooks/` (23 `.md` files; "twenty-three playbooks", [README.md:38](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/README.md#L38); index at [skills/poteto-mode/SKILL.md:125-147](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/SKILL.md#L125-L147)). They are: investigation, bug-fix, perf-issue, hillclimb, runtime-forensics, trace-forensics, feature, refactoring, prototype, visual-parity, authoring-a-skill, eval, babysit, shipping, autonomous-run, orchestrate, autopilot-full, autopilot-stack, session-pickup, pause-safely, multi-phase-plan, worktree-cleanup, opening-a-pr.
- **24 principles**, 24 `skills/principle-*/` directories. The README says "twenty-four short skills, one principle each." ([README.md:204](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/README.md#L204)).

## Philosophy

- "throughput without quality is not a goal i aspire to. if you want to go fast, go deep first." ([README.md:5](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/README.md#L5))
- "the goal is not to maximize loc, in fact it's the opposite. pstack helps you write less, but higher quality code." ([README.md:7](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/README.md#L7))
- "**pstack gives you fearless parallelism.** when you can go deep on one agent and trust it to write good, verifiable code, you can truly parallelize with confidence." ([README.md:9](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/README.md#L9))
- "fork it. improve it. make it yours." ([README.md:13](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/README.md#L13))
- "personally, i don't believe in planning. the best spec is code." ([README.md:250](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/README.md#L250)). The same line ends "if you do want to make a plan, [`/poteto-mode`] covers it, but it's not a default."
- "pstack has no planning skill, on purpose." ([docs/guide/04-design.md:103](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/docs/guide/04-design.md#L103))
- "You plan through code: prototypes answer the open questions, a README or tutorial sets the target, and the written plan comes last." ([docs/guide/04-design.md:5](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/docs/guide/04-design.md#L5))
- On verification: "Make the agent able to do it, and you stop being the bottleneck." ([docs/guide/06-verify-and-ship.md:5](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/docs/guide/06-verify-and-ship.md#L5))
- On autonomy: "Make the loop autonomous only after all four hold. Until then, run it while you watch." ([docs/guide/07-overnight.md:16](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/docs/guide/07-overnight.md#L16)). The four conditions are at [07-overnight.md:11-14](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/docs/guide/07-overnight.md#L11-L14). You did the task by hand or watched an agent do it. The agent has the tools you would use, such as the verification skill. Every stage proves its work and can stop the line. You turned repeated failures from transcripts into tools, skills or checks.

## Long-running chat vs orchestrate

**Autonomous run** (`skills/poteto-mode/playbooks/autonomous-run.md`). One chat drives one task to one predicate. "**You own the exit condition. Define done, then drive to it without stopping.**" ([:3](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/autonomous-run.md#L3))

- Finish condition first: "State the exit condition as a checkable predicate before the first iteration (tests green, repro fixed, all N PRs merged, pixel-diff zero)." ([:5](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/autonomous-run.md#L5)). It is never relaxed: "never relax the predicate to declare victory." ([:11](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/autonomous-run.md#L11))
- Wake: "Pick the wake mechanism using Cursor's `/loop` command (a built-in, not a pstack skill)." If there is an event to watch, a watcher subagent wakes the chat, with a long heartbeat as fallback. With no event, it uses a fixed heartbeat ([:6](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/autonomous-run.md#L6)).
- Don't stop to ask: "Do not park reversible work for the human or use `AskQuestion`." It surfaces only irreversible actions, product calls no experiment can settle, or a real dead end ([:9](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/autonomous-run.md#L9)).
- Decision log: "Checkpoint every iteration via the **show-me-your-work** skill, a row for what changed and whether the predicate moved." ([:10](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/autonomous-run.md#L10)). The TSV columns are `ts phase decision why evidence result` ([show-me-your-work/SKILL.md:27](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/show-me-your-work/SKILL.md#L27)).
- Delegation: the playbook does not mention it. It comes from poteto-mode. Spawned helpers are `poteto-agent` "(code-writing delegates, ad-hoc helpers)" ([poteto-mode/SKILL.md:93](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/SKILL.md#L93)). The Feature playbook makes it mandatory: "Delegate code-writing to a subagent" … "Mandatory: no skip-with-reason escape" ([feature.md:12](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/feature.md#L12)).
- When: "**Autonomous run.** A long task to drive to completion without stopping ("run until done", "/loop until X")." ([poteto-mode/SKILL.md:139](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/SKILL.md#L139))
- There is a middle tier. Big step-away work "routes to the **figure-it-out** skill even when a narrower playbook like Feature fits", and "figure-it-out designs one bespoke run, orchestrate runs the program." ([poteto-mode/SKILL.md:123](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/SKILL.md#L123)). The guide's overnight example routes the same way ([07-overnight.md:38](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/docs/guide/07-overnight.md#L38)).

**Orchestrate** (`skills/poteto-mode/playbooks/orchestrate.md`). One standing coordinator chat runs a program. "**You own the program, never the code. Author briefs, drain the queue, keep the frontier green, decide.**" ([:3](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/orchestrate.md#L3))

- Coordinator: "It never authors or edits code." There is one exception. It may land a verified unit mechanically (a fast-forward or clean cherry-pick, then push) where local git is cheap ([:15](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/orchestrate.md#L15)).
- State on disk in `orchestrate/<project-slug>/`, where "Every file has exactly one writer." ([:23](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/orchestrate.md#L23)). `preferences.md` holds the standing orders, pasted verbatim into every spawn and resume ([:25](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/orchestrate.md#L25)). `units.tsv` "has one row per unit: id, track, state, branch, PR, head SHA, brief path." ([:27](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/orchestrate.md#L27)). `gates.md` "parks human gates (question, options, default on no answer)" ([:30](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/orchestrate.md#L30)). There is also an `inbox/`, `frontier.json`, `decisions.tsv` and a `status.md` derived from the tables ([:26-32](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/orchestrate.md#L26-L32)).
- The ledger: `ledger.tsv` keeps one verdict per PR plus head SHA, one of `live-ui-verified | unit-test-verified | type-check-only | verifier-blocked | verifier-failed`. "CI green is an input to a verdict, not a verdict." A new head SHA voids the row ([:89](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/orchestrate.md#L89)).
- Briefs: "The brief is the product. A vague brief fails quietly, because a worker cannot ask you a question." ([:11](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/orchestrate.md#L11)). The fields are GOAL, SCOPE, CONTEXT, ACCEPTANCE, VERIFY, TIMEBOX, FORBIDDEN, REPORT and STANDING ([:38-50](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/orchestrate.md#L38-L50)). One unit is piloted end to end before fan-out ([:62](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/orchestrate.md#L62)).
- When: "For a whole project handed to one standing coordinator chat: multi-day, many stacked PRs, dozens to hundreds of subagents, the human checking in twice a day instead of every five minutes." ([:3](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/orchestrate.md#L3)). The guide calls it "deliberately heavy machinery." ([07-overnight.md:86](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/docs/guide/07-overnight.md#L86))

**The threshold, in her words.**

- "Route here when the work outlives any single agent. Work one agent could finish inside the session's budget is not a program." ([orchestrate.md:3](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/orchestrate.md#L3))
- In the first step: "If one agent could finish inside that budget, stop here and run Autonomous run instead." Also: "By roughly 70% of it, stop spawning and land what is verified." ([orchestrate.md:60](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/playbooks/orchestrate.md#L60))
- In the router: "Work one agent could finish inside the session's budget routes there, not here, however program-shaped the phrasing sounds." ([poteto-mode/SKILL.md:140](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/poteto-mode/SKILL.md#L140))
- Our reading: the test is capacity, not wording. If one agent can finish inside the session budget, use one chat. Otherwise use a coordinator.

## Verification skill

`/create-verification-skill` interviews "the repo, not the user" about the app's surface, how it runs, how to drive it, what can be observed, and whether two instances can run in isolation ([create-verification-skill/SKILL.md:11-19](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/create-verification-skill/SKILL.md#L11-L19)). It writes this ([:9](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/create-verification-skill/SKILL.md#L9), [:25-36](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/create-verification-skill/SKILL.md#L25-L36)):

```
.cursor/skills/verify-<app>/
  SKILL.md          frontmatter: name verify-<app>; description names app, surface, when to use
                    sections: Launch, Doctor, Drive, Evidence, Cleanup, Helpers
  features/
    README.md       index of the map
    <feature>.md    one per user-facing feature; seed the top 3-5
  <scripts>         helpers, executable, invocation shown in SKILL.md
```

- **Launch.** The exact start command and a ready signal, starting from an empty data dir with migrations and seed data. "Ready means usable, not just that a process answers." It includes teardown ([:27](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/create-verification-skill/SKILL.md#L27)).
- **Doctor.** "one read-only check that answers "is this instance worth driving?"" It checks that the process is up, the build is right, the port is ours and auth is valid ([:28](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/create-verification-skill/SKILL.md#L28)).
- **Drive.** Real selectors and commands from this repo, preferring stable handles ([:29](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/create-verification-skill/SKILL.md#L29)). **Evidence.** It drives the real user path, captures both the action and the resulting state, and checks side effects ([:30](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/create-verification-skill/SKILL.md#L30)).
- **Cleanup.** "Never kill by process name; kill what you started." Proof artifacts survive teardown ([:31](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/create-verification-skill/SKILL.md#L31)). **Helpers.** "A helper the reader has to reverse-engineer is not a helper." ([:32](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/create-verification-skill/SKILL.md#L32))
- **Feature file.** An H1 and one paragraph, then exactly four H2s in order: `Sub-features`, `How to get to it (user POV)`, `Driving it with <harness>`, `Gotchas`. `Driving it with` opens with `Preconditions:`, then labelled bullets that pair each action with an exact command and an observable result ([feature-map-example/README.md:35-40](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/create-verification-skill/references/feature-map-example/README.md#L35-L40)). The example index has these sections: Baseline preconditions, Driving conventions, Proof and skip reporting, Feature entry contract, Features. A journey is never weakened to make it pass ([SKILL.md:36](https://github.com/cursor/plugins/blob/1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def/pstack/skills/create-verification-skill/SKILL.md#L36)).
- **Hand-over gate.** The generator runs the new skill once: launch, doctor, drive one mapped feature, capture evidence, clean up. Then it checks that the evidence still exists.
